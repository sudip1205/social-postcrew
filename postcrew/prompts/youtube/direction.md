For every scene except the closing card, decide:
1. PURPOSE: hook, setup, explanation, example, reveal, summary or cta.
2. VISUAL: the one concrete picture that shows the idea: real objects, real data, a diagram that grows. Never "text explaining X".
   A problem is shown happening; a number is shown counting; an algorithm is shown running on real values; a mistake is shown failing.
3. FOCUS: the single thing the viewer must look at. It is the highlighted part of the picture.
4. BEATS: what appears, in the order the voice names it, one beat every 2-4 seconds. A scene with nothing new for longer than the house
   style allows is a still picture: give it more beats or a different layout.
5. LAYOUT: the layout that draws it best: diagram or flow for things that connect, send or store; trace for an algorithm on an array;
   grid for ANY problem on a grid, matrix or board (it draws real rows and columns; a trace is one row and cannot show above or below);
   codeviz for recursion or a table filling; code for a program and its output; stat for a real figure; points only for a short list;
   title or statement only for the opening or a single strong line.
6. PATTERN: use a pattern offered for the scene when it fits, by name.

Make it ONE video: say in "concept" which picture grows through it (the same diagram gains boxes, the same array is reused), so consecutive
scenes share elements instead of cutting to something new. Vary layouts: never the same one three times in a row; at most a third words-only.
The hook (scene 1) shows the problem as a picture within 2 seconds.
