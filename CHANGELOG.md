# Release notes

## 0.2.0: YouTube, per-app settings and a faster Studio

### New
- **Videos use the blue Signal look by default.** Only Signal (blue) is ticked in the Factory at first. Story (the cast) and VS Code are used only when you tick them there. With only Signal ticked, every video is made in the blue look as before: explainer or algorithm, Short or long.
- **Pick the video looks in the Factory, and mix them in one video.** The Factory has a Looks row: Signal (blue), Story (cast) and VS Code. The ticked looks go to the Factory chat and to the crew's Script Writer, and a video uses only those.
  - **One video, several looks:** a video can switch looks scene by scene, and the factory makes each part with its own renderer, then joins them with one caption file.
  - **Long algorithm videos:** explain each idea on the blue board, then type and run the code in a real VS Code (code-server on the lab, recorded, with the camera zooming on the lines the narrator names), approach by approach.
  - **Where each look may go:** Story is used in Shorts only, VS Code in long algorithm videos only.
- **Explainer Shorts are cartoon stories; algorithm videos keep the Signal look.** This is the owner's rule from 2026-11-12. A Short that explains what something is and how it works:
  - is told by the channel's fixed cast (Max, Lily, Jake, Olivia, Grace, Tom) as an everyday story, in a background that fits it (library, office, server room, street, kitchen, classroom, home or warehouse);
  - draws the idea on that background's board;
  - ends with a scene that pairs each part of the story with the real tech term.

  Algorithm problems keep the Signal look, with code and traces. The Script Writer is sent back when an explainer isn't a story. Only the narrator speaks: characters talk in short tooltips, and their own voices are built but switched off.
- **Shorts are at most 60 seconds, and they are visual explainers.** This is the owner's rule after an analysis: the Shorts had grown to 2–3 minutes, viewers watched 20–40% of them, and daily views were falling.
  - A Short is now made at most 60 seconds long (160 words of narration). The Script Writer is sent back when a script is longer, and the factory refuses to voice or render one.
  - The planner no longer proposes coding builds: "Build an API Gateway in Python" is refused, and "What Is an API Gateway and How It Works" is planned instead.
  - Code scenes are only allowed in algorithm videos.
- **Shorts are narrated in the channel's own voice, `dip_puck`.** The owner's recordings, converted to an American male sound and trained into a voice model on the lab, replace Kokoro Echo. The lab serves it at `127.0.0.1:8882` with the same API as Kokoro (other voices pass through to Kokoro), and the Shorts factory uses it for every video. When an episode's own recording is removed, it goes back to `dip_puck`.
- **Old videos go to the NAS instead of being deleted.** With `cleanup.archive_dir` set (the lab: `/mnt/diptodive`, the TrueNAS share `CLOUDBEE/DipToDive`), only today's videos stay on this machine: the daily clean-up copies every finished video from an earlier day (`media/`, the Reel folders in `instagram/`, loose videos) to `<archive>/<YYYY-MM>/<area>/`, checks the copy's size, and only then deletes it (`cleanup.archive_after_days` keeps more days; videos still queued to post are never moved). Pictures and other files keep the 30-day rule. When the NAS is not mounted, the videos stay where they are until it is.
- **Two posts never share a media file.** A Short made in chat and the scheduled Short for the same day and plan slot got the same post id, so the second video overwrote the first one's file (and its Instagram folder). A taken id now gets `-2`, `-3`, …
- **Shorts too long for Instagram's API wait in a folder, ready to post by hand.** Each one goes to `workspace/instagram/<date>-<title>/` with `video.mp4`, `cover.jpg`, `caption.txt` and `details.txt` (length, YouTube and Facebook links, the steps to post it in the Instagram app, which takes 3 minutes).
- **The daily clean-up covers everything older than 30 days.** On top of runs, media, cache and briefs it now deletes old `motion/` clips, folders in `instagram/`, `*.bak*` backups and, with `cleanup.factory` on (the lab), the Shorts factory's episodes (script, voice, render) and renders in `episodes/` and `out/`, judged by their newest file. The factory's code, skill, music and secrets are never touched.
- **Shorts longer than 45 seconds skip Instagram, with a reason.** Instagram's API accepts Reels only up to 45 s from your account (tested: 38 s and 45 s go through, 48 s and longer are refused, whatever the file size). A longer Short is marked "too long for Instagram's API" instead of failing five times with error notices. Facebook still gets every Short.
- **Instagram uploads work.** Instagram refuses a direct upload made with a Page token (it stores 0 bytes). Its calls now use the system-user token (`userAccessToken` in the factory's `secrets/meta.json`), and Facebook keeps the Page token.
- **Facebook and Instagram Reels get a cover picture.** Postcrew picks the frame of the hook with the most on screen (its headline and picture drawn) and sets it as the Facebook cover; Instagram gets the same moment as its cover frame.
- **Every Short that goes to YouTube also goes to Facebook and Instagram as a Reel.** Right after the YouTube upload, Postcrew posts the same video to your Facebook Page and Instagram (a port of the factory's `pipeline/meta-publish.mjs`: Facebook Reels upload, Instagram resumable upload with the Facebook copy as fallback). It uses the factory's `secrets/meta.json`. The caption is the title, the description's first paragraph and its hashtags (no #Shorts, within Instagram's limits). A failed Reel never stops the YouTube upload; a Short longer than 90 s (the Facebook Reels limit) goes to Facebook as a Page video: you get a notice, and it is tried again at the next publish windows (up to 5 times), never posted twice. The YouTube notice links the Reels.
- **The Factory chat changes the skill the moment you tell it to.** The working copy from the last release did not work: the chat still edited `.claude/skills/...` directly, was refused every time, and saved your rules in its own memory or in `shorts-factory/SKILL-PENDING-UPDATES.md` instead. Now a Claude Code hook catches every Edit or Write to the skill, does it on the working copy and saves the file into the skill at once, so later steps of the same turn already read the new rule. The chat says "Skill updated: <file>" as each edit lands, and it is told never to keep your rules anywhere but the skill.
- **The Factory chat can really run the algorithm solver now.** The first rule was written `Bash(python3 algo/:*)`, which this Claude Code (2.1) never matches (`:*` only counts at a word boundary), so the chat was still refused; the rules are now `Bash(python3 algo/*)`, `Bash(npx hyperframes check *)` and so on, each tested on the lab, including the chat's `cd shorts-factory && ...` form.
- **The Factory chat can run algorithm solvers and check its pages.** It may now run `python3 algo/<name>.py` (the skill makes algorithm videos from the code's real output), `npx hyperframes check`, `lint` and `snapshot`, and ffmpeg frame grabs; before, it stopped and asked you to approve them, which nobody can do while it runs. It is told to use those forms and never to ask for approval. The scheduled writer can run the algo solvers too.
- **My voice: a whole take is cut where each scene really starts.** The split matches the words you said to the script's words, so a slip or an extra word no longer shifts the cuts, and the outro is matched to the line it actually reads when its scene has no text of its own (the first live test put most of the outro into the scene before it). The My voice dialog shows that outro line too, so you know what to read.
- **Your own voice in a Factory video, and names from the US or UK only.** Each Factory video has a My voice button: upload a recording of the whole script (a phone voice memo is fine) and faster-whisper splits it into scenes by the words you say, cutting in the pauses; or upload or replace one scene. Listen back to each scene, switch any of them back to Kokoro, then Make it again with my voice: the factory uses your recordings, with captions timed to what you actually said, and Kokoro only for scenes you did not record. Your own voice counts as its own narrator in the variety check. The skill now says a script that needs a person's name uses a common American or British first name, nothing else.
- **Every YouTube Short must differ from the recent ones (for monetisation).** The Shorts factory has a variety check (`npm run variety`): each episode names its story shape, hook, voice and pace, and is refused before any work when it repeats the last videos' shape, hook, voice (three in a row), scene order (80 % the same), first words, title pattern or sign-off. The skill's new references/variety.md has the eight story shapes, seven hooks and eight voices (plus blends) to rotate through; the scheduled writer and the Factory chat run the check and fix the script until it passes. The outro keeps its look but is worded fresh each time.
- **The Factory chat can change the skill at last.** Claude Code never lets it write inside `.claude/`, so every skill change it tried was refused ("Claude requested permissions"), and lasting instructions given in the chat were lost. Now each turn gets a fresh copy of the skill in `~/Youtube/skill-edit/`; Claude edits that, and the Studio copies whatever changed back into the skill when the turn ends (nothing is deleted from the skill) and says which files it updated.
- **Study several reference videos together, and add more at once.** Pick two or more reference videos (or Pick all) and Study together: Claude gets every video's frames and comments, plus what you want it to look for across them, finds the pattern they share (hook, pacing, captions, colours, motion, ending) and writes only that into the skill, listing each rule with the videos that show it. Add more opens the add box again; it takes several files at once and several links (one per line); links that fail stay in the box to retry.
- **Factory videos leave the list once queued or deleted, and reference videos teach the skill.** Move to Queue and Delete worked but the list was never redrawn (the button you clicked kept the focus, and the list is not redrawn while you are in it); now a queued video's files move to out/queued/ (the Queue has its own copy) and it leaves the Factory, as a deleted one does. A new Reference videos panel takes a video you like, uploaded or from a link (yt-dlp, 720p), with your comment on what to learn from it; ffmpeg takes 12 frames from it, and Teach the skill sends Claude those frames, the video and your comment so it writes the lesson into the skill as a concrete rule. References live in ~/Youtube/references/, outside the factory.
- **Move to Queue on the Factory page works, and you check the YouTube title, description and tags first.** The button never answered: its request was read twice, and the second read waited forever (the Studio now reads a request once, for every route). Each Factory video now has YouTube details, its title (with a 100-character count), description and tags from the episode's youtube.json, editable; Move to Queue saves them back to youtube.json and queues the video with them, and refuses a missing or too-long title, < or >, or tags over 500 characters.
- **Factory: make a video from one of your plans, and every scheduled video follows the skill as it is now.** Use a plan on the Factory page fills the message from one of your YouTube plans in Manual run (your words, how you want it made, the problem read from your files, and the files themselves for Claude to open); moving its video to the Queue marks the plan as made. The scheduled Script Writer now reads the skill (SKILL.md, its Owner rules and the references it points to) and CLAUDE.md from disk before writing, with the Skill tool allowed, so a rule taught in the Factory chat applies to the next scheduled video; each run records the skill version it used, shown on the Factory page.
- **Factory videos can be moved to the Queue or deleted.** Each video on the Factory page is a row with its thumbnail (click to watch), a date and Move to Queue, and Delete (removes the rendered video, thumbnail and captions; the script stays so Claude can make it again).
- **Factory: talk to Claude Code in your Shorts factory from the Studio.** A new Factory tab is a chat, like the Claude Code app, with Claude Code running in ~/Youtube on the Studio's computer. Give it a topic and it writes and renders the Short; give it an instruction for every video and it writes it into the explainer-short-style skill (the factory's CLAUDE.md rule). The chat carries on until New chat. Beside it: the rendered videos to watch, each with Queue (a date, then the usual approval and upload), and the skill files with when each last changed. Claude never uploads from the chat.
- **YouTube videos are made by your Shorts factory.** The YouTube crew is now Topic, Script Writer, Render and Publisher. The Script Writer is Claude Code started inside ~/Youtube, so it follows the factory's CLAUDE.md and explainer-short-style skill and writes episodes/<slug>/script.json and youtube.json for the day's plan; Render runs `npm run make` (Kokoro voice, HyperFrames, FFmpeg); the Publisher queues the video with the factory's thumbnail and youtube.json title, description and tags. The researchers, Editor, Creative Director, Storyboard Artist, voice, video, Video Editor, Hooks and Quality Director steps no longer run for YouTube. The factory itself is used unchanged; its folder is video.factory_path, else ~/Youtube/shorts-factory.
- **Missed posts can be run, and a schedule without topics keeps its weekdays.** A config from before the monthly plan was switched to "dates only" whenever an app had no topics, so no month plan was written and nothing was scheduled: it now keeps its weekday schedule. The Overview lists the scheduled posts of the last 7 days that were never made (the Studio was off, or the run failed) with Run, Skip and Run all; the scheduler makes them one at a time, oldest first, when it has nothing of its own to do.
- **A graph problem is drawn as a graph.** A custom plan whose files the Reader read as a graph stopped with "the video cannot draw that yet". A new `graph` scene draws the problem's own nodes and edges (weights and one-way edges too, up to 12 nodes), placed by the app in layers from the start node (top to bottom in a Short, left to right in a long video), and walks them as the voice speaks: the node worked on, the ones done, the queue or stack waiting, the edges followed and a value on a node ("B=4"). The app refuses an edge or a step that names a node the graph does not have. A graph problem must now be drawn in at least two graph scenes, as a grid problem is; trees, linked lists, stacks and intervals still stop the run.
- **Alice, Bob and Eve are drawn side by side, and a clock is a clock.** In the Diffie-Hellman Short every two-party scene was a column (Alice, Eve, Bob), so Eve looked like a relay in the middle, the arrow labels were too small to read and "a clock of thirteen" was three boxes. A diagram of two parties and one listener (Eve, an attacker, the open network) now puts the sender on the left, the receiver on the right, the wire between them with its labels under it, and the listener above the wire with a dashed tap; a scene about someone in the middle keeps the chain. A diagram that names a clock of N is drawn as a clock face with N marks and a hand that goes round from 0 to the number, lap by lap, and stops where it lands ("2 laps of 13 + 6, 32 lands on 6"). Arrow labels on a Short are a third bigger, and diagrams use more of the frame. The Quality Director no longer sends a script the owner approved back to be rewritten: layout, label size and empty space are redraws, and a video that still looks weak waits for approval.
- **A re-run can keep the script the Editor nearly passed.** The Diffie-Hellman script rose 68, 72, 74 and 78 over four Editor rounds and the run stopped one fix short of 80, after $4.10 of its $5 had gone on the script. `/api/runs/rerun` with `"keep_script": true` starts a new run that keeps the failed run's topic, research and script and the Editor's last scores (marked approved by the owner), so it goes straight to the Creative Director, voice and video. The kept steps are used once: if a later step sends the work back, they run again.
- **A letter used as a name is said as the letter, and the Editor no longer fails its own wording.** The Diffie-Hellman re-run failed after four Editor rounds: in round 3 the Editor asked for "a prime number called p, and a base called g"; in round 4 it raised the red flag "unpronounceable" for that lone "p" and "g" and asked to remove them. A lone lowercase letter (other than "a" and "I") is now given to the voice as a capital, which it says as the letter name, and the Editor is told that a capital letter used as a name is fine and that it must never flag wording it asked for itself: if its own wording has a flaw it gives the corrected wording without lowering the score.
- **Numbers worked out on screen are run, step by step, and an explainer is detailed, adult and code-free.** In the Diffie-Hellman Short, Bob's "2 to the 5 is 32, which wraps to 6" was an arrow label ("2^5 = 32 = 6"), "216 mod 13 = 8" was one trace step, and Alice's three multiplications flashed by in under a second: the viewer had to pause three times. Any calculation on the example must now be a **run** scene in every video, not only algorithm videos: the writer writes a few lines that do it, the app runs them and draws each operation as its own step ("x = 8 * 2 = 16", then "x = 16 mod 13 = 3"), one sentence each. A new check (no AI) sends back any other scene that shows an equation or narrates arithmetic, including scenes redesigned by the Graphics agent or the Quality Director. Run scenes may start from a one-value list that grows, and show % as "mod". Explainers (anything that is not an algorithm or a coding solution) now have no code scenes, draw each step of the mechanism as its own diagram with a box for every party and value, and explain in detail for adults: the rules no longer say "as to a child" or "words a ten-year-old follows".
- **A failed run can be run again, and a run's cap counts retries.** Today's 10:00 YouTube run (Diffie-Hellman) failed the moment the Quality Director asked for a redraw: "the run used all 16 attempts". The cap counted every step's first try, and a YouTube run has 12 steps, so two writer and two editor retries used it up and the redraw the Quality Director had already designed (12 scenes, voice kept) never ran. The cap (Settings, "Retries per post") now counts only retries; the $5 budget and 4 tries per step still stop a run that keeps failing. And the Workflow's **Re-run** button now works on a failed run: it starts a new run for the same app, date and topic (the day's plan, which a failed run never used up) and opens it.
- **The voice says API and AI.** In "MCP vs API" the voice said "a PI" for API and "eye" for AI: acronyms are spelled out letter by letter for the voice ("A P I"), and Kokoro reads a leading "A" as the word "a" ("A P I" was heard as "a PI", "A I" as "our eye", "A W S" as "a WS"). A spelled acronym that starts with A now has its letters joined ("A-P-I", "A-I", "A-W-S"; a plural is written as the word Kokoro knows, "APIs"), which Kokoro says letter by letter; tested by voicing each form and transcribing it. The voice server's cache was keyed by the written narration, so a fix to how a word is said reused the old recording: it is now keyed by what is said.
- **Run now makes the plan you clicked.** Run now on the API security plan made the day's Game Server video again: since several videos a day, a scheduled plan still to make came before your own plans on the day, and the vetoed Game Server plan was back to "still to make". The plan you click Run now on is now the one made, until it is in the Queue; then the day's scheduled plan is next again.
- **An explainer is drawn, not coded, and "Does that make sense?" is optional.** A concept video ("how API security works", "what is a JWT") was forced to have a code scene and the algorithm arc's "ways to code it", so the Script Writer invented code and puzzles nobody asked for. The writer now picks the kind of video: an explainer follows one real-life scenario end to end with every hop drawn (who sends what, who checks it, what is allowed or blocked) and needs no code; a problem is traced and coded; a build is coded and run. The "builds or solves nothing" check now applies only to algorithm topics, and the Editor never asks an explainer for code. Check-ins such as "Does that make sense?" are optional (at most once in a Short, never filler): the only rule left is one real question the video answers.
- **Several videos a day, each at its own time.** An app's schedule can list run times (`schedule.generate_times`, e.g. `["10:00", "17:00"]`): the scheduler makes one video at each, the day's next plan still to make, and a run that is still going when the next time comes delays it rather than skipping it. The month's plans follow: YouTube writes enough plans for every run of the month (one more per topic to run by hand), and placing plans fills every day's first slot, then every day's second, never putting the same topic twice on one day. Videos still wait for your approval when the app's approval is manual.
- **Every algorithmic video runs its code, not only your own plans.** A YouTube topic can now be marked algorithmic (`platforms.youtube.algorithm_topics`): every plan made from it is an algorithm video wherever it is scheduled, as the "Algorithm video" box does for your own plans. A category can be marked too (`"algorithm": true`), for the days a category is run without a plan. On the lab, "Solve Algorithmic Problems" and the two LeetCode categories ("Short: algorithm explained", "Long: solve an algorithm problem, step by step") are now algorithm videos.
- **A run starts from where the code starts, and a new diagram starts clean.** In the algorithm test video the Kadane run began on day two: the state the loop starts from (current = best = 2) is set before the loop, so it was never shown. The state when the outermost loop holding the `# step` line first starts is now the run's first step. And the "Two ways" diagram inherited the three boxes of the diagram before it ("5 numbers", "15 runs", "Same sums") though it shared none of them: boxes now carry over only into a diagram that continues the same picture (shares a box with it).
- **An algorithm video runs the simple way first, and only run scenes do the arithmetic.** The first algorithm-mode test video drew its run scenes well, but the Script Writer still followed the usual arc, whose "visual" part comes before the ways and had to be a drawing: so it taught Kadane with hand-drawn diagrams ("adding gives one, so we start fresh") before brute force ran, and the Quality Director sent it back until the run ran out of attempts. In an algorithm video the run scenes are now the "visual" part (the simple way run step by step), a scene that narrates calculations on the example must be a run scene, the first walk-through must be the code with the most nested loops, and nothing before it may teach the idea. The writer is given the arc part by part.
- **Algorithm videos: the app runs the code and draws what really happened.** Add your own plan (YouTube) has a new **Algorithm video** box. Ticked, the Script Writer no longer types the board's steps by hand: it writes the solution code, marks one line with `# step`, and a new **run** scene (algotrace.py) runs that code on the example in a locked-down Python process (no network, no files written, no other programs, 10 s, 1 GB) and records every time that line finishes: the array, the pointers, the variables and the calculation that changed them, worked out from the real values ("current = max(4, -2 + 4) = 4"). Those recorded steps are the picture: big cells, an arrow per pointer, a lit window, each variable as a big tile and the calculation under the board, so a step cannot be skipped, a sum cannot be wrong and a count cannot jump. The narration is one sentence per recorded step (at least 5 words, saying the calculation), and each step starts as its sentence is said; when they do not match, the writer is sent the real list of steps to narrate. In an algorithm video a hand-written trace, grid or codeviz walk-through is refused, and at least two run scenes are needed (the simple way and the better way). Unticked, the plan is made the usual way (system design and concept videos). The plan card shows "Algorithm: code is run".
- **A diagram that grows over several scenes stays still, and every counter is a big tile.** In the rebuilt Kadane Short the "three ways" diagram ran over four scenes and was laid out again from each scene's arrows: with one arrow the boxes stood in a column, then went back to a tree, and Kadane jumped to the top. Consecutive diagram scenes with the same boxes are now laid out once from all their arrows, so only the arrows appear. A counter written "current -2" (no equals sign) is now a big tile like "current = -2".
- **Walk-throughs go slowly, the code says what the voice says, and the picture keeps time.** From the Kadane Short: at 0:14 the voice said "three ways" over a big "0 ways" (the number counted up from 0, and started when the voice said the heading's words, not the number); at 1:06 the numbers on the arrows sat beside their badges; the voice promised three ways but only two were coded, and called brute force n cubed over a brute.py of two loops (n squared); kadane.py was typed out three times; and at 1:59 five Kadane steps flashed by in one second. Fixes: a big number appears as the voice says that number, and a small count shows as itself; arrow badges are centred; code scenes in a row with the same code are one editor (typed once, terminal run once); the voice's pauses are matched to where each sentence should end, not to the longest breath (which had pushed all five steps into the scene's last second), and a match that squeezes a sentence past any real pace is not used. New checks (no AI) send a script back when a walk-through has under 6 words a step (each step its own sentence with its calculation), when the time it gives an approach is not the loop nesting of the code shown for it, or when it promises N ways and codes fewer. The Script Writer is told the same.
- **A post made by hand, or one of your own plans, no longer uses up the day's scheduled run.** On 4 November the YouTube schedule made nothing: that day had two plans (Build a REST API, and Kadane's Algorithm), the REST API one was made by hand at 00:28, and two of your own plans were run from Manual run, so at 18:00 the scheduler found "a post already dated today" and skipped the day, silently, every tick. Now, on a day with plans, the scheduled run is skipped only when none of the day's scheduled plans is left to make, and it makes the next one still to make (a plan waiting in the Queue, yours or one made by hand, no longer stands in front of it). A day without plans still counts any post for that date.
- **Walk-throughs and code fill the screen on a phone.** The Quality Director kept scoring Shorts about 33/100 for the same reasons: an array walk was a thin row of small cells in the top third with the rest of the frame black, a ten-cell array was ten tiny boxes, and code shrank until a long line fit, down to about 25 px. A trace now sits in the middle of the frame with cells as large as the width allows (a Short wraps more than six cells into two rows), a big note, and each counter as a large tile ("count = 2" is a COUNT tile reading 2). Code is never under 38 px on a Short: a long line wraps with its indent kept, instead of the whole file shrinking, and the editor is centred.
- **Every step the voice counts is shown, or the scene goes back.** In the Subarray Sum Short at 2:39 the voice counted eight windows on a ten-box shelf, but the screen showed three steps (count 1, then 5, then 8), and the "length minus window plus one" scene stated four windows over two. Nothing compared a walk-through's steps with what the voice said: the Script Writer and the Storyboard Artist wrote steps by hand and skipped, and a long trace was split in two and its second half redrawn from nothing. New checks the app runs itself, no AI (fidelity.py), on every trace and grid scene from any agent (writer, Storyboard Artist, the Quality Director's redesigns): a counter (count, matches, windows, pairs...) goes up by at most one per step, carrying on from the scene before, so every thing counted is shown being counted (a count needing more than 12 steps needs a smaller example); the number of boxes the voice names is the number drawn; the count the voice ends on is the count the last step shows; a sum on a step is correct and adds the lit boxes' numbers; each step's cue words are in the narration. A scene that breaks one is sent back to its author, and a redesign that breaks one is refused. A trace is no longer split across scenes. The Script Writer, Storyboard Artist and Quality Director are told the same rule.
- **The closing card is drawn as icon buttons, as the voice asks.** The end card ("Like · Comment · Subscribe") came in after the voice had said it, as plain words. Two causes: the voice's own closing silence was taken for a pause between sentences, so every scene's word times were pulled towards its end (in the Two Pluses closing, "subscribe" was drawn 1.3 s after it was said); and the closing card was drawn by HyperFrames as words, though Remotion already had icon buttons. A silence that runs to the end of a voice file is now the closing silence, so cues land on their words in every scene, and the closing card is always drawn by Remotion: a thumb, a speech bubble and a bell, each with its word, appearing just before the voice says it and pressed when it does.
- **What the voice says is what the board shows.** In the Two Pluses rebuild, at 0:45 the voice said "walk left and you find four good cells" but the four cells never lit: a step's cue was found at the first word matching any of its words, so "walk right" was timed at the "Walk" of "Walk left", both steps landed at 0.0 s and the later one hid the earlier. A cue of several words is now found where its words are said together, else at its rarest word, and a step never lands on the moment of the one before it (grid and trace scenes). At 0:14 the voice said "green cells are good, red cells are bad" over a board with no green or red: the voice copied the PDF's picture. A grid can now colour its cells by character ("G=green", "B=red"), and a grid scene whose narration names a colour the board does not show is sent back to the writer.
- **Every problem is drawn as its own shape, on its own example, or the run stops before spending anything.** The Two Pluses video went wrong because nothing named what the problem's data looked like, so a grid was squeezed into the one picture available. Now (shapes.py): the **Reader names the data shape** of the problem it reads (array, string, grid, number table, counting ways, tree, graph, linked list, stack or queue, intervals), and the topic's words name it when there are no files. A shape the video can draw must be drawn with its own picture in at least two scenes (a grid with grid scenes, an array with traces), or the script is sent back. A shape it cannot draw yet (tree, graph, linked list, stack or queue, intervals), when the Reader named it, **stops the run at the topic step**, before any writing, and Run now refuses it with the reason; the plan card says so. When the problem came from files, the video must work the **problem's own sample** (a sample board or array copied exactly), not a made-up one. The video ends with its own closing card, "Like · Comment · Share", that appears one second after the last point, each word as it is said. The closing line defaults to "If this was useful, please like, comment and share it with someone who would find it helpful."; change it in Settings. A calmer gap (0.6 s) follows every scene in every renderer, and captions are six words at a time.
- **The quality check no longer calls a dark page a black frame.**
- **Open the Studio to your local network.** `python3 -m postcrew serve --lan` (or `--host <address>`) lets other computers on your network use the Studio, for example from a lab server. It stays on this computer only unless you ask. On the network it needs an access token: the server prints a link ending `/?token=...` that opens the Studio and keeps you signed in with a cookie; the token is made once and kept in `studio-token` in the workspace (or pass `--token` / `$POSTCREW_TOKEN`). Writes must come from the page the Studio served. LinkedIn and YouTube sign-in still return to localhost, so connect those accounts on the server itself or through an SSH tunnel.
- **A monthly plan you assign by hand.** Settings > Topics is now a list of one-line topics per app (LinkedIn and YouTube): no details, add as many boxes as you like and save. On the 1st of every month Postcrew writes 10 related plans for each topic, with the context, research topics, a real-world example and the takeaway. They are not put on days: the Plan page is a month calendar plus the list of generated plans, and you assign each plan to a date (for YouTube also Short or Long). Only assigned days get a post. Published plans stay listed, struck through, and are never planned again; no plan repeats another or a published post. Topics changed in the middle of a month are used for the next month's plan (or press Generate plan). The weekly cadence, one-off dates and the weekly planner are gone from Settings; an existing weekly schedule is switched to assigned dates.
- **Remotion is now the video renderer.** Every YouTube video is drawn by Remotion (React) by default: title, statement, points, code, diagram, flow and trace scenes, timed to the recorded voice, with captions that follow the words. Needs only Node.js 18+; the first run installs the project (`postcrew/remotion`) and Remotion fetches its own browser. The thumbnail is drawn by the same project. The picture is made by three steps you can watch in the Workflow view: **HyperFrames Producer** (HeyGen, HTML + GSAP: the opening card and big statements, with drifting colour, blur-in words and a highlighted key word), **Remotion Producer** (diagrams, flows, traces, code, lists) and **Video Composer** (joins the clips in scene order, lays the voice under them, makes the thumbnail). Each drawing step shows its engine and a live progress bar; if HyperFrames cannot run, Remotion draws every scene. No watermark, handle or brand text is drawn on the picture or thumbnail. The older renderers stay available per app or per topic in Settings.
- **Hooks agent: a quality gate for every video.** A new step ("Hook") looks at the finished video before it is queued, with no AI, in
  seconds: sound where the voice should speak (missing sound, long silences, wrong loudness, clipping), the voice against the
  punctuation and the words, and the frames (black frames, a picture frozen for ages, an empty scene, things drawn at the edge).
  For an explainroo video it fixes only what is wrong, once: a scene with missing sound is recorded again, a scene with an empty or
  crowded picture gets one scoped round from the picture agent, then it renders again. A fault it cannot fix does not fail (and
  re-run) the whole video: the video is held for your approval with the findings, whatever the approval setting.
- **Cheaper production.** A retry of the video step keeps the pictures already drawn when the script is the same; fix rounds name the
  scenes to change and leave the others alone; the picture agent's second look is off by default because the Hooks agent checks the
  frames for free (turn it on in Settings if you want it).
- **The voice stops where the punctuation says.** Measured on real ElevenLabs output: a comma could run on with no pause (0.0 s), and a
  misplaced "..." stopped the voice in the middle of a phrase for 0.6 s. Now clause commas get a small break, list items keep the
  voice's own breath, sentence ends and "..." beats keep theirs, and the writer is told to put "..." only after a complete sentence
  (the checks send a script back for one in the middle of a phrase). After the voice is recorded the Explainroo Producer listens
  (explainroo aligns every word): a scene whose stops are in the wrong places is recorded again with another seed, up to twice.
- **Space and spacing in Explainroo videos.** The agent is told the free area in pixels and must use all of it; explainroo's check now
  also reports texts closer than 28 px, content that stops short of the free area, text under 44 px on a phone and a scene that
  fills too little of the height, and the agent fixes them before the render. Subtitles default to the very bottom (88%).
- **Nothing is left for the voice to guess.** Before narration goes to ElevenLabs, every symbol, number and acronym is written out as the
  words to be said (`postcrew/speech.py`): "O(n^2)" becomes "O of n squared", "9 - 7 = 2" becomes "nine minus seven equals two",
  "95%" and "$4.50" and "20ms" become words, acronyms are said the way people say them (A P I, sequel, cube control for kubectl) and
  unknown ones are spelled letter by letter. Following ElevenLabs' guidance that too many break tags cause artifacts and noises, at most
  three pauses are added per request.
- **Unspeakable text is caught.** The writer's automatic checks send a script back for code, identifiers, addresses, emoji, lone letters,
  words with no vowels or mixed letters and digits; the Editor sees what the voice will actually be given and has a new red flag,
  `unpronounceable`, for anything a voice could not say.
- **Closing line in every video.** The writer ends each video with a call to action ("If you like this kind of content, please like,
  comment and subscribe. And if you don't like it, definitely tell me why in the comments..."); the checks send a script back without
  it. Edit or switch it off in Settings > YouTube > Closing line.
- **More room at the edges, subtitles lower.** Pictures stay further from the sides of the frame and the subtitles sit near the bottom
  (adjustable per Settings > YouTube > Explainroo). Explainroo has no such setting, so a small patch
  (`postcrew/tools/explainroo-layout.patch`) is applied to your install automatically.
- **Explainroo renderer.** Videos can be made by [explainroo](https://www.explainroo.com), an open-source tool that runs on your computer:
  hand-drawn lines, icons, charts, code, a camera that follows the narration, sound effects and quiet music. The approved ElevenLabs
  voice is used as its narration; an AI agent writes the pictures from the script's plan, explainroo's own layout checks are fed back
  until clean, the agent looks at each scene's last frame and fixes what is wrong, then it renders and verifies. Choose it under
  Settings > YouTube > Video renderer (or per topic). See docs/video-and-voice.md.
- **Less like a slide deck.** Boxes are drawn as solid 3D blocks that float gently; the blocks a scene will need are faintly outlined
  before they are named, so the screen is never empty; data dots keep flowing along every arrow; dust drifts and the camera pushes in
  slowly. Statement scenes get a large illustrated object, and bullet lists sit in the middle of the screen.
- **A more human voice.** ElevenLabs is asked for a less flat delivery (lower stability, some style), capitalised ordinary words
  ("UP", "NOT") are read as words instead of letters (real acronyms like API and TCP are still spelled out), and the writer is told to
  talk to one viewer with varied rhythm and small reactions. An algorithm video must contain a trace scene and a system-design video a
  flow scene, or the script is sent back.
- **Videos that show the example moving.** New `trace` scenes (an example array whose pointers slide, with the sum or decision for each
  step and a hash map of what is remembered) and `flow` scenes (one real request travelling between components with the actual data on
  each arrow). The writer prompt, the topic briefs, the Editor's rubric and the Video Editor all ask for them: an algorithm video must
  show the two-pointer pass on a real array; a system-design video must follow one request through the boxes.
- **Multiple apps.** LinkedIn and YouTube each have their own schedule, planning, topics, publishing settings and crew run.
  Frequency can be weekly, every N days or a list of dates, with a time per weekday or per date.
- **YouTube crew.** Script Writer, Editor, Voice (ElevenLabs), Video Producer and Publisher. Scripts are checked and reviewed
  like posts (length against words per second, scenes, title, description, tags). Voice and video are only made after the
  Editor passes, so a rejected script costs no voice characters. Shorts (9:16, up to 60 s) and long videos (16:9).
- **Official YouTube upload.** OAuth from the Studio, resumable upload, thumbnail, scheduled publishing, practice mode.
- **Bring your own.** Upload your own script, voice or finished video for any date; they are checked, and a script is still
  reviewed.
- **Diagram scenes.** Boxes and arrows that build up while the voice explains them, for system design, architecture
  components, cryptography and algorithms. In your own script: `flow: Client > Gateway > Service`.
- **Blackboard renderer and the Chalk agent.** Draw-and-explain videos: the voice is recorded first, then each stroke is drawn
  when the narrator says it (word times are estimated from the text). Chosen per app or per topic. Needs only Pillow and ffmpeg.
- **Explainer renderer (new default).** A slow, clean animated explanation modelled on KodeKloud and TechPrep: one picture that
  grows across scenes, icon boxes that pop in as they are named, arrows that draw themselves with a travelling dot, the current
  thing glowing while the rest dims, handwritten chapter titles, caption chunks timed to the voice. The writer and the Editor
  are trained on this structure.
- **Slow pace setting** and **Shorts up to 3 minutes** (was 60 seconds).
- **Video Editor (a second review, after the video is drawn).** For blackboard videos the new step measures each box, arrow and bullet
  against the recorded voice (pauses in the real audio), fixes a different order for free, lets an AI reviewer replace graphics that
  do not follow the narration, and draws only the changed scenes again. The voice is never generated again. The Queue shows the
  sync score.
- **Animation MCP option.** Optionally render scenes with an MCP server; falls back to the built-in renderer.
- **Ideas with context.** `Title :: context` ideas (up to 600 characters) and per-topic context and planning notes now reach the
  planner and the script writer.
- **New Studio design.** The Studio follows a saved Stitch design (icons, colour-coded status chips, tooltips), built without a
  JavaScript build step. `scripts/stitch_sync.py` and `scripts/stitch_check.py` keep it faithful.

### Changed
- **Scripts that pass the Editor.** The Week Planner now knows how long each video is and plans one main idea per video (about one
  idea per 25 seconds) instead of bundling several subtopics. The writer is told the length is a hard limit and that the brief's
  beats are one sentence each in a Short; standard concepts need no source but are worded carefully, and examples are introduced
  as examples. The Editor judges a video brief as a guide (a short beat counts, no asking for words over the budget, layouts are
  the writer's choice) and flags `unsupported_claim` only for specific numbers, defaults and named-product behaviour.
- **Teaching tone.** Scripts are written like an online lesson: simple English, short sentences, technical terms used by their
  real names and explained the first time they appear. New automatic check: no sentence over 30 words.
- **Natural pauses for ElevenLabs.** Full stops, question marks and "..." become timed pauses (`<break>` tags) when the voice is
  requested; the script text stays clean.
- **Fewer tokens per piece.** Anthropic prompt caching, cache-aware cost, per-run token accounting and an Editor that stops
  re-reading once a read fails.
- `video.renderer` accepts `ffmpeg`, `blackboard` or `mcp`; a topic may set `renderer` and its own `format` / `target_seconds`.
- The Studio stylesheet `style.css` is replaced by `studio.css` and a compiled `tailwind.css`.

### Known limits
- ElevenLabs, the YouTube upload and a real animation MCP server have only been tested with fakes.
- Unverified Google apps upload as private until Google audits them; uploads share a daily quota.
- Blackboard timing inside a scene is estimated, not read from the voice service. Very long videos render slowly.
- The hand-written chalk font is used when the system has one (Chalkboard, Marker Felt); otherwise Inter Bold.
